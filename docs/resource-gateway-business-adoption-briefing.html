采用问题 · 为什么先进方式也可能难以推广

学习门槛是真实风险，产品需要主动吸收复杂度

业务团队不应被要求一次性理解新的语法、工具链和工程流程。采用设计的第一原则，是保留业务控制权并降低认知负担。

业务管理者的合理顾虑

  • 是否需要学习 DSL 或像研发人员一样工作。
  • 现有经验、流程和岗位职责是否会被突然改变。
  • 智能体生成错误内容时，谁承担业务责任。
  • 验证流程是否过重，反而拖慢低风险变化。
  • 既有系统、审批和回滚机制是否仍然有效。

产品需要提供的采用保障

  • 表单、模板、对话和业务差异视图作为默认入口。
  • 智能体只生成候选方案，不能绕过验证与批准。
  • 草案、低风险变化和高风险变化采用分层门槛。
  • 现有流程在试点期继续运行，正式变化可回滚。
  • 用真实基线评估学习成本、周期、返工与风险。
采用判断：如果平台只是把技术复杂度转嫁给业务人员，试点就不应扩大。

从「配置执行」转向「意图、约束与验收」

业务人员的专业判断进入正式资产和发布证据；机械配置、技术检索和重复验证由平台与编码智能体承担。

采用问题 · 如何降低一次性迁移风险

从旁路观察开始，每一步都用业务证据决定是否继续

现有流程、人工门禁和回滚能力在试点期间继续存在。阶段完成不等于模块建成，而是业务价值和风险条件同时满足。

阶段一

旁路观察

不改变现有生产流程，记录资产、依赖、人工步骤和等待时间。

退出：现状基线清楚，业务人员无需承担新操作
阶段二

智能草案

业务人员通过模板或自然语言提出变化，智能体生成候选方案。

退出：差异可理解，草案准确率和修订成本可接受
阶段三

受控发布

在可隔离、可回滚的场景中接入验证、审批和准确版本。

退出：周期或返工改善，且无高风险绕过
阶段四

规模复用

把经过验证的资源、规则、流程和场景推广到更多团队。

退出：第二场景无需维护专属运行分支
停止条件：学习成本过高、业务价值不清、证据不足或风险边界不可控时，不进入下一阶段。
责任问题 · 引入智能体后谁负责什么

智能体扩大执行能力，业务责任仍由明确角色承担

新工作方式把原本散落在会议、页面和人工记录中的责任显式化，让目标、生成、验证和批准分别归属清楚。

01

业务 Owner

定义目标、适用范围、正确结果标准、风险边界和业务例外。

保留：最终业务判断与发布批准
02

编码智能体

检索已有资产、生成最小差异、补充验证场景并根据诊断修复草案。

限制：不能自行定义业务正确性
03

平台与研发团队

负责连接适配、运行稳定、权限、隔离、工具链和产品体验。

责任：把技术复杂度留在平台
04

质量与风险团队

制定覆盖政策、风险分级、证据要求、例外期限和审计规则。

责任：门槛与业务风险相匹配
衡量问题 · 如何判断试点真的更好

先记录现状，再同时衡量效率、质量与采用体验

不预设收益数字，也不使用单一综合分数隐藏风险。试点前由业务、平台、质量和财务共同确认口径。

交付周期从业务意图到可验证发布候选同时包含生成、验证和批准等待。
人工负担操作步骤、等待时间和跨团队沟通判断是否真正减少机械配置。
采用体验草案接受率、修订次数和学习反馈识别产品是否转嫁了复杂度。
正确性关键条件覆盖与未覆盖分母通过不等于覆盖完整，缺口需要可见。
风险质量生产误触、未授权写入和回滚事件高风险动作应保留人工门禁和审计。
核心指标是「可验证业务资产交付周期」：同时衡量速度与正确性，任一恶化都不算成功。
决策请求 · 现在需要批准什么

批准一个可控试点，以证据决定是否扩围

先选择一条真实业务流程，在不替换生产流程的前提下验证采用体验、交付效率和风险质量。

建议批准的五项事项

  1. 选择一个高变更、多依赖、可隔离、可回滚的业务流程。
  2. 指定业务 Owner、平台 Owner 和质量／风险负责人。
  3. 授权采集当前周期、人工步骤、返工和质量基线。
  4. 先运行旁路观察与智能草案，不直接替换生产流程。
  5. 以业务指标、采用反馈和风险证据决定是否进入受控发布。

业务管理者保留的选择权

草案不准确，可以退回；验证证据不足，可以暂停；学习成本过高，可以调整入口；风险边界不清，可以停止扩围。

Resource Gateway 的成功标准直接落在业务体验上：业务人员减少机械操作，获得更清楚的判断依据，并保持对关键变化的控制。

常见疑问：业务人员需要学习 DSL 吗？现有系统是否需要替换？

DSL：不作为业务人员的默认入口。表单、模板、对话和业务差异视图承担日常任务，DSL 作为平台内部的标准资产形式。

现有系统：不要求一次性替换。Resource Gateway 与现有 API Gateway、工作流、业务系统和集成平台组合，先旁路观察再逐步迁移。

智能体错误：智能体只生成候选方案，不能绕过结构检查、隔离测试、覆盖策略、权限和人工批准。

业务人员少做配置，多做判断；系统少依赖经验，多依赖可验证证据。
