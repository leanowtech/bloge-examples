# S1-D 治理资产与授权引用解析实现说明

本文记录 [`rg-evolution-design-1.2.1.md`](./rg-evolution-design-1.2.1.md) 阶段一 `S1-D` 的实现边界、信任转换和验收证据。当前状态为 `IN_PROGRESS`。在持久化、授权、分级负载托管和端到端引用运行全部形成固定证据前，不得将 `S1-D` 或 `S0-EXIT-03` 标记为已完成。

## 目标与边界

`S1-D` 解决四个问题：

1. 逻辑资源契约、世界模型和剧情成为可跨进程恢复的不可变治理资产；
2. 请求头只携带精确资产引用，大型 fixture 和真实业务负载不进入传输层；
3. 服务端在读取资产前，根据可信调用身份完成租户和用途授权；
4. 合成、脱敏和真实负载按治理策略分级托管，执行内核仍只接收编译后的 fixture 值。

本阶段不引入 registry、发布门禁、审批工作流、通用对象存储协议或新的执行内核。世界资产编译后仍进入现有 `FixtureBundle`、`ExecutionControlCompiler`、`TestRunService` 和证据管线。

## 三类不可变资产

统一资产目录只接受以下三种类型：

| 类型 | 稳定标识 | 版本来源 | 内容指纹 |
|---|---|---|---|
| `LOGICAL_RESOURCE_CONTRACT` | `contractId` | 治理信封中的递增版本 | 由契约规范内容重算 |
| `RESOURCE_WORLD_MODEL` | `worldModelId` | 模型自身版本，必须与治理版本一致 | 由模型构造器重算 |
| `SCENARIO` | `scenarioId` | 剧情自身版本，必须与治理版本一致 | 由剧情构造器重算 |

逻辑资源契约本身保持版本无关。租户和版本只存在于治理信封，不反向污染 `LogicalResourceContract` 领域对象。

资产地址固定为：

```text
tenantId + kind + id + revision + fingerprint
```

禁止 `latest`、模糊标识、仅按 id 解析或相信调用方提供的指纹。创建使用 `expectedHeadRevision = 0`，落库为版本 `1`；更新只能从 `N` 生成 `N + 1`。并发冲突失败，不跳过版本，也不覆盖历史行。

## 持久化与完整性

资产目录复用现有 PostgreSQL/H2、头表、历史表和 JSON blob 模式。数据库是权威来源。读取时必须同时核验：

- 行中的租户、类型、标识和版本与查询坐标一致；
- JSON 中的资产身份与行身份一致；
- JSON 只能通过现有领域构造器或工厂重建；
- 重建后的领域指纹与行指纹、精确引用指纹一致；
- 世界模型和剧情的内部租户、版本与治理信封一致。

错误引用返回未命中；权威行损坏、JSON 漂移或指纹漂移返回固定的完整性错误。错误信息不得包含 JSON、context、expectation、世界规则或其他业务负载。

内存缓存不是权威。若启用缓存，每次受治理读取仍需证明数据库行未被替换或损坏；不能以性能优化为理由掩盖持久化漂移。

## 引用解析信任链

服务端按以下顺序处理资产引用：

1. 入口解析并限制 `X-BLOGE-Test-*` 控制头；
2. 校验可信身份、环境、purpose 和 correlation；
3. 使用可信身份中的 `tenantId` 与信封分支确定资产坐标；
4. 在调用资产仓库前执行租户、用途和主体授权；
5. 只读取无负载的治理元数据；
6. 根据数据来源、安全分级、保留期和访问策略执行第二次授权；
7. 读取并校验精确资产版本；
8. Scenario 引用继续解析其精确 World Model 依赖；
9. 唯一解析兼容世界切片，编译并通过统一内核运行。

第一阶段授权被拒时，资产仓库调用次数必须为零。第二阶段授权被拒时，不得读取 JSON payload。租户信息只取自认证上下文，不能取自请求体、请求头中的资产内容或已解析 JSON。

## 分级负载托管

负载治理使用彼此独立的维度：

- 数据来源：`SYNTHETIC`、`REDACTED`、`REAL`；
- 安全分级：沿用企业身份的 clearance 语义；
- 保留策略：明确到期时间和到期后的失败关闭行为；
- 访问策略：稳定策略引用，由治理层解释。

`REAL` 负载必须同时满足显式允许、安全分级、保留期和访问策略。`REDACTED` 不等于公开数据，仍可能要求较高 clearance。分类、租户、保留期和授权决策不得进入 `FixtureRule`、`CompiledExecutionControl` 或执行引擎的领域类型。

## 确定性切片选择

引用式运行没有调用方提供的 provider 选择。系统根据 Scenario 的逻辑契约依赖，在精确 World Model 中解析兼容切片：

- 每个依赖恰好有一个兼容切片时生成 `WorldSliceSelection`；
- 没有候选时失败关闭；
- 多个候选时以 `SELECTION_NOT_UNIQUE` 失败，禁止“第一个优先”；
- 与 Scenario 无关的世界切片不参与选择；
- 结果按逻辑契约标识规范排序，不受输入顺序影响。

显式选择仍保留给低层编译器测试和受控调用方；自动选择只负责引用式高层入口。

## 交付切片

### D1：治理资产仓库（`DEVELOPMENT_VERIFIED`）

- 统一三类资产的头版本和不可变历史；
- CAS 递增版本和精确引用；
- 规范编解码和每次读取的完整性复核；
- H2 跨仓库实例恢复、租户隔离和篡改测试。

当前实现使用统一头表和历史表保存三类资产。领域指纹用于精确引用，独立的 `record_fingerprint` 覆盖完整规范 JSON，避免 World Model 领域指纹未覆盖的 binding 字段发生静默漂移。`LogicalResourceBinding` 通过受控恢复工厂重建，不使用反射绕过领域边界。

D1 聚焦集为 `12/12`，覆盖三类资产往返、CAS 递增版本、真实并发单赢家、旧版本不可变、租户与类型隔离、跨仓库实例恢复、错误指纹未命中、头行和历史行篡改、严格信封字段，以及内部租户和版本漂移拒绝。加入阶段一已有契约、世界模型、剧情、编译和运行测试后的世界层回归为 `90/90`。

### D2：授权优先的引用解析（`DEVELOPMENT_VERIFIED`）

- 从认证上下文构造租户精确地址；
- 粗粒度授权先于任何仓库读取；
- 元数据授权先于 payload 读取；
- 拒绝、越权、过期和指纹漂移使用净化错误。

D2a 已实现精确引用的第一层授权。租户只取自认证上下文；资产类型只取自信封的 Scenario/World 分支。顶层拒绝时资产仓库调用为零。Scenario 恢复通过调用方提供的受控依赖解析器读取 World Model，先授权 World 精确地址，再读取世界行。错误的 Scenario 指纹在依赖回调前返回未命中，数据库行与规范信封漂移则返回完整性错误。

持久化层只允许自身定义的固定、无负载依赖中断类型穿过编解码错误净化，任意运行时异常不能携带业务内容逃逸。D2a 聚焦集为 `22/22`，加入阶段一资产、世界、剧情、编译和运行测试后的回归为 `102/102`。

D2b 已落地独立于执行内核的负载治理模型。数据来源固定为 `SYNTHETIC`、`REDACTED`、`REAL`，安全分级固定为 `PUBLIC`、`INTERNAL`、`CONFIDENTIAL`、`RESTRICTED`；每个不可变版本同时保存保留期限、访问策略引用、可选审批引用和覆盖完整资产坐标及全部治理字段的治理指纹。兼容写入默认使用 `SYNTHETIC + PUBLIC`，未显式修改治理信息的更新继承当前头版本策略；`REAL` 写入必须包含审批引用和相对于仓库固定时钟仍在未来的保留期限。

读取固定为“坐标授权 → metadata-only 查询 → 元数据完整性与到期校验 → 分级策略授权 → payload 查询”。metadata-only SQL 不选择 `canonical_json`；仅配置坐标授权、元数据过期、策略拒绝、错误 metadata 坐标或错误治理指纹时，payload 查询均为零。Scenario 的 World 依赖重复同一顺序，不使用顶层授权结果替代依赖授权。D2 聚焦集为 `34/34`，加入阶段一资产、世界、剧情、编译和运行测试后的联合回归为 `114/114`。

### D3：引用式统一运行

- Scenario 与 World Model 精确依赖解析；
- 唯一世界切片自动选择；
- `WorldScenarioCompiler` 与 `WorldScenarioRunService` 接线；
- 请求体仍只承载业务输入；
- 生产目的在入口和服务端继续双重拒绝。

## 验收矩阵

| 编号 | 必须证明的事实 | 权威证据 |
|---|---|---|
| `S1-D-01` | 三类资产均可创建、递增更新和读取历史版本 | 真实 H2 仓库测试 |
| `S1-D-02` | 旧版本不可变，过期 CAS 不能覆盖头版本 | 并发与历史测试 |
| `S1-D-03` | 精确引用包含租户、类型、标识、版本和指纹 | 引用值对象与负向测试 |
| `S1-D-04` | 重启后的新仓库实例可读取并重验资产 | 同一数据库跨实例测试 |
| `S1-D-05` | JSON、行身份或指纹篡改被检测且错误无负载 | 数据库故障注入测试 |
| `S1-D-06` | 未授权和越权请求在仓库读取前失败 | 带读取计数哨兵的授权测试 |
| `S1-D-07` | 高敏或过期负载在 payload 读取前失败 | 元数据/payload 分层探针测试 |
| `S1-D-08` | 世界切片零匹配、多匹配均失败 | 自动选择组件测试 |
| `S1-D-09` | 请求头只包含引用，大型 payload 不进入协议值或日志 | 协议边界与日志负向测试 |
| `S1-D-10` | Header → 授权 → 解析 → 编译 → 执行 → 证据完整跑通 | 真实 Spring 系统测试 |
| `S1-D-11` | 任一生产隔离层失守时服务端仍拒绝控制计划 | 入口/服务故障注入矩阵 |
| `S1-D-12` | Resource Gateway 与 Test Kit 全量回归保持绿色 | 两个 `clean verify` 命令 |

## 当前状态

`D1` 和 `D2` 已形成开发验证证据。确定性切片选择组件另有 `7/7` 聚焦测试，并已按“唯一命中或失败”规则固定。`S1-D-01` 至 `S1-D-08` 的组件级事实已有固定证据；`D3`、真实请求头端到端系统测试、生产隔离故障注入和双项目里程碑回归仍未闭合。因此 `S1-D` 保持 `IN_PROGRESS`，阶段零的 `S0-EXIT-03` 仍保持 `PARTIAL`。
